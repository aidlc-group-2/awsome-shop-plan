## 2. 业务背景与目标

AWSomeShop 是面向企业内部员工的福利积分电商平台。员工通过"AWSome 积分"兑换预选商品；管理员/HR 负责商品管理、积分发放与订单处理。目标是以 MVP 验证员工积分兑换系统的商业模式。

**成功标准（MVP）**
- 员工可完成"浏览 → 兑换 → 查看订单/历史"的完整闭环
- 管理员可完成"商品管理、积分发放/调整、兑换记录处理"的完整闭环
- 系统满足既定性能、安全与可访问性指标

## 5. 功能性需求（Functional Requirements）

按工作单元/领域服务组织。每条需求带唯一编号（FR-x）。

### 5.1 认证服务（Auth Service，Unit 2，:8001）

- **FR-A1 员工自助注册**：员工可使用企业邮箱自助注册账号。
- **FR-A2 邮箱域名限制**：注册仅允许配置的企业邮箱域名（白名单），非白名单域名拒绝注册。
- **FR-A3 登录与 JWT 签发**：用户名/邮箱 + 密码登录，校验通过后签发 JWT（含用户 ID 与角色）。
- **FR-A4 密码安全**：密码使用 bcrypt 加密存储；不以明文存储或返回。
- **FR-A5 角色管理**：用户具备 EMPLOYEE 或 ADMIN 角色；新注册默认 EMPLOYEE。
- **FR-A6 注册联动积分**：新账号注册成功后触发"入职奖励"积分发放（见 FR-P3，跨服务事件）。
- **FR-A7 令牌校验接口**：为网关提供 JWT 校验/解析能力（或采用网关本地校验公钥）。

### 5.2 商品服务（Product Service，Unit 3，:8002）

- **FR-PR1 商品 CRUD**：管理员可创建、编辑、上下架、删除商品（名称、描述、积分价格、库存、图片、分类、商品类型）。
- **FR-PR2 商品类型**：商品分为**实物商品**与**虚拟商品/卡券**两类（见第 7 节履约流程）。
- **FR-PR3 二级分类管理**：支持两级分类（父分类/子分类）的新增、编辑、删除（树形结构）。
- **FR-PR4 商品浏览与搜索**：员工可按分类浏览、按关键字搜索、查看商品详情。
- **FR-PR5 库存管理**：管理员可调整库存；商品库存为 0 时标记为"售罄"。
- **FR-PR6 图片上传**：管理员可上传商品图片，存储于本地文件卷（Docker Volume）。
- **FR-PR7 库存查询/预占接口**：为兑换服务提供库存查询、预占与扣减接口（见 FR-O3）。

### 5.3 积分服务（Points Service，Unit 4，:8003）

- **FR-P1 积分余额查询**：员工可查询当前积分余额。
- **FR-P2 积分变动记录**：记录所有积分变动（发放、扣减、兑换消费、退回、过期），员工与管理员可查询。
- **FR-P3 入职奖励发放**：新员工注册时自动一次性发放入职奖励积分（额度可配置）。
- **FR-P4 周期性发放**：按可配置规则周期性（如每月）自动发放积分。
- **FR-P5 积分规则配置**：管理员可配置积分发放规则（入职奖励额度、周期性发放额度/周期）。
- **FR-P6 手动调整**：管理员/HR 可手动为指定用户发放或扣除积分，并记录原因。
- **FR-P7 积分过期**：积分具有有效期，到期后自动过期失效并记录变动；过期规则可配置。
- **FR-P8 兑换扣减/退回接口**：为兑换服务提供积分扣减（兑换时）与退回（取消时）接口。

### 5.4 兑换服务（Order Service，Unit 5，:8004）

- **FR-O1 创建兑换订单**：员工选择商品并提交兑换；校验积分余额与库存。
- **FR-O2 积分校验与扣减**：下单时校验积分充足并扣减相应积分（调用积分服务）。
- **FR-O3 库存预占**：下单时**预占库存**（非立即扣减），发货后正式扣减（实物商品；虚拟商品见第 7 节）。
- **FR-O4 无需审批自动成功**：库存充足且积分足够时，订单**自动成功**进入履约流程，无需管理员审批。
- **FR-O5 配送信息（实物）**：实物商品兑换需填写配送信息（收件人、地址、联系方式）。
- **FR-O6 发货状态跟踪（实物）**：管理员可更新发货状态（待发货/已发货/已完成等）。
- **FR-O7 兑换取消与退回**：**发货前**员工可取消订单，取消后积分自动退回、预占库存释放。
- **FR-O8 订单详情与历史**：员工可查看订单详情与个人兑换历史。
- **FR-O9 兑换记录管理**：管理员可查看/管理所有兑换记录。
- **FR-O10 跨服务一致性（Saga 补偿）**：积分扣减、库存预占、订单创建跨服务操作失败时执行补偿（释放预占、退回积分），保证最终一致性。

### 5.5 API 网关（Unit 6，:8080）

- **FR-G1 统一入口**：所有前端请求经网关转发到对应微服务。
- **FR-G2 认证校验**：网关统一校验 JWT，未认证请求拒绝。
- **FR-G3 权限控制**：基于角色（EMPLOYEE/ADMIN）对管理端接口做访问控制。
- **FR-G4 路由转发**：按路径将请求路由到 auth/product/points/order 服务。
- **FR-G5 安全防护**：协助实现 CSRF/XSS/SQL 注入防护、限流等横切关注点。

### 5.6 前端应用（Frontend，Unit 1，:3000）

- **FR-F1 员工端页面**（9 个）：登录、商城首页、商品详情、确认兑换、配送信息、兑换成功、订单详情、兑换历史、积分中心。
- **FR-F2 管理端页面**（7 个）：仪表盘、商品管理（卡片）、商品详情、分类管理（树形表格）、积分规则管理、兑换记录管理、用户管理。
- **FR-F3 弹窗/对话框**（10 个）：商品下架确认/调整库存/上传图片/编辑；分类新增/编辑/删除确认；积分规则新增/编辑；发货状态修改；用户积分调整。
- **FR-F4 详情页面**（2 个）：兑换记录详情、用户积分变动记录。
- **FR-F5 双语切换**：界面支持中英文切换（i18n）。
- **FR-F6 SPA 路由与鉴权**：基于角色展示员工端/管理端，未登录跳转登录页。

### 5.7 基础设施（Infrastructure，Unit 7，:3306）

- **FR-I1 容器编排**：提供 docker-compose 一键启动全部服务、网关、前端与 MySQL。
- **FR-I2 数据库初始化**：MySQL 创建 4 个独立 Schema 并初始化表结构。
- **FR-I3 网络与服务发现**：服务间通过容器网络互通。
- **FR-I4 持久化卷**：MySQL 数据与上传文件使用 Docker Volume 持久化。

## 7. 关键业务规则与履约流程（Business Rules）

### 7.1 积分规则
- **BR-1** 入职奖励：新员工注册成功后一次性发放（额度可配置）。
- **BR-2** 周期性发放：按可配置周期与额度自动发放。
- **BR-3** 积分过期：积分有有效期，到期自动失效并记录；积分消耗按**先进先出（FIFO）**顺序（优先消耗最早获得/最早到期的积分）。
- **BR-4** 余额不足：兑换时积分不足则拒绝下单。

### 7.2 兑换与库存流程
- **BR-5** 下单自动成功：积分足够 + 库存充足 → 订单自动成功，无需审批。
- **BR-6** 库存预占：下单预占库存，发货后正式扣减（实物）；预占失败则下单失败。
- **BR-7** 取消与退回：发货前员工可取消，积分自动退回、预占库存释放。
- **BR-8** 超兑防护：悲观锁保证并发下不超兑。

### 7.3 实物 vs 虚拟商品履约（✅ 已确认）
> 商品为"实物 + 虚拟混合"。以下履约规则已由用户确认：

- **AS-1（实物商品）**：需填写配送信息；流程为 下单成功 → 库存预占 → 管理员发货（扣减库存）→ 完成；发货前可取消。
- **AS-2（虚拟商品/卡券）**：无需配送信息；下单成功后**即时发放/履约**（无"待发货"环节）；其"取消窗口"可设为履约完成前（若即时履约则不支持取消）。
- **AS-3**：商品实体含"商品类型"字段以区分两类流程。

## 10. 需求摘要（Summary）

AWSomeShop 是一个 Java + Spring Boot 微服务、React + TypeScript 前端、Spring Cloud Gateway 网关、MySQL 8.4 多 Schema、Docker 编排的内部积分电商 MVP。核心闭环包括：员工自助注册（企业邮箱）并获入职奖励积分、浏览/搜索商品、以积分兑换实物或虚拟商品（下单预占库存、无需审批自动成功、发货前可取消退回）、查看积分与订单历史；管理员负责商品与二级分类管理、积分规则配置与手动调整、兑换记录与发货管理、用户管理。系统强调悲观锁并发控制、Saga 补偿的跨服务一致性、双语 i18n、WCAG 2.1 AA 可访问性，以及面向大型组织的性能与容量目标。

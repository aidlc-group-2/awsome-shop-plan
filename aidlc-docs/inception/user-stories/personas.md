# 用户画像（Personas）

> 阶段：INCEPTION - 用户故事
> 来源：README 用户画像 + requirements.md
> 时间：2026-06-10T15:40:33+08:00

本系统在权限模型上分为 EMPLOYEE 与 ADMIN 两类，但在体验设计上区分以下 3 类画像。

---

## P1 · 技术型员工（Technical Employee）

| 维度 | 描述 |
|------|------|
| **角色** | 软件工程师 / 技术岗位员工（权限：EMPLOYEE） |
| **技术熟练度** | 高 |
| **目标** | 快速浏览、搜索并兑换心仪商品；随时掌握积分余额与到期情况 |
| **痛点** | 流程冗长、页面加载慢、搜索不精准、积分到期无提示 |
| **典型行为** | 直接搜索目标商品、关注积分明细、期望高效完成兑换 |
| **关注点** | 性能、信息密度、键盘/可访问性 |

---

## P2 · 非技术行政员工（Non-technical Admin Staff）

| 维度 | 描述 |
|------|------|
| **角色** | 行政 / 运营等非技术岗位员工（权限：EMPLOYEE） |
| **技术熟练度** | 中等偏低 |
| **目标** | 在清晰引导下完成商品浏览与兑换，查看自己的兑换历史 |
| **痛点** | 界面复杂、术语难懂、操作步骤不清晰、出错后不知如何处理 |
| **典型行为** | 按分类浏览、依赖引导式流程、需要明确的成功/失败反馈 |
| **关注点** | 易用性、清晰文案、双语支持、错误提示友好 |

---

## P3 · HR 管理员（HR Administrator）

| 维度 | 描述 |
|------|------|
| **角色** | HR / 平台管理员（权限：ADMIN） |
| **技术熟练度** | 中等 |
| **目标** | 维护商品与分类、配置与发放积分、处理兑换与发货、管理用户 |
| **痛点** | 批量操作繁琐、缺少数据概览、积分调整需可追溯、发货状态难跟踪 |
| **典型行为** | 查看仪表盘、配置积分规则、手动调整积分、更新发货状态、查询用户积分变动 |
| **关注点** | 数据准确性、操作可审计、效率、权限安全 |

---

## 画像与角色映射

| 画像 | 系统角色 |
|------|----------|
| P1 技术型员工 | EMPLOYEE |
| P2 非技术行政员工 | EMPLOYEE |
| P3 HR 管理员 | ADMIN |

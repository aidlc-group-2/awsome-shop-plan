# 用户故事（User Stories）

> 阶段：INCEPTION - 用户故事
> 分解维度：用户旅程式（User Journey-Based）
> 验收标准格式：Given-When-Then
> 可追溯性：每条故事标注关联需求条目（FR-x）
> 优先级：MoSCoW（Must / Should / Could / Won't）
> 画像：P1 技术型员工、P2 非技术行政员工、P3 HR 管理员
> 时间：2026-06-10T15:40:33+08:00

故事均遵循 INVEST 原则（独立、可协商、有价值、可估算、小、可测试）。

---

# 旅程 1 · 账号与认证（员工）

## US-01 员工自助注册
- **画像**：P1, P2
- **优先级**：Must
- **关联需求**：FR-A1, FR-A2, FR-A4, FR-A6
- **故事**：作为一名新员工，我希望使用我的企业邮箱自助注册账号，以便登录并开始使用积分兑换福利。
- **验收标准**：
  - Given 我在注册页填写了企业白名单域名邮箱与符合强度要求的密码，When 我提交注册，Then 账号创建成功、密码以 bcrypt 加密存储，并自动发放入职奖励积分。
  - Given 我使用非白名单域名邮箱，When 我提交注册，Then 系统拒绝并提示"仅支持企业邮箱注册"。
  - Given 邮箱已被注册，When 我再次提交，Then 系统提示该邮箱已存在。

## US-02 员工登录
- **画像**：P1, P2
- **优先级**：Must
- **关联需求**：FR-A3, FR-G2
- **故事**：作为一名员工，我希望使用邮箱/用户名与密码登录，以便访问我的积分与兑换功能。
- **验收标准**：
  - Given 我输入正确的凭据，When 我登录，Then 系统签发 JWT 并进入对应（员工/管理员）首页。
  - Given 我输入错误的密码，When 我登录，Then 系统提示凭据无效且不泄露具体错误项。
  - Given JWT 已过期，When 我访问受保护页面，Then 系统跳转登录页要求重新登录。

## US-03 退出登录
- **画像**：P1, P2, P3
- **优先级**：Should
- **关联需求**：FR-A3, FR-G2
- **故事**：作为一名用户，我希望能安全退出登录，以便保护我的账号。
- **验收标准**：
  - Given 我已登录，When 我点击退出，Then 本地令牌被清除并跳转登录页。

# 旅程 2 · 浏览与搜索商品（员工）

## US-04 浏览商城首页商品
- **画像**：P1, P2
- **优先级**：Must
- **关联需求**：FR-PR4, FR-F1
- **故事**：作为一名员工，我希望在首页浏览可兑换商品列表，以便发现我感兴趣的福利。
- **验收标准**：
  - Given 存在已上架商品，When 我打开商城首页，Then 我看到商品卡片（图片、名称、积分价格、库存状态）。
  - Given 商品库存为 0，When 列表展示该商品，Then 其标记为"售罄"且不可兑换。
  - Given 商品较多，When 我浏览列表，Then 支持分页或滚动加载且页面加载 < 3s。

## US-05 按分类浏览商品
- **画像**：P2
- **优先级**：Should
- **关联需求**：FR-PR3, FR-PR4
- **故事**：作为一名员工，我希望按商品分类（含二级分类）浏览，以便快速定位某类福利。
- **验收标准**：
  - Given 存在两级分类，When 我选择某父分类或子分类，Then 列表仅展示该分类下的商品。

## US-06 搜索商品
- **画像**：P1
- **优先级**：Should
- **关联需求**：FR-PR4
- **故事**：作为一名员工，我希望通过关键字搜索商品，以便快速找到目标商品。
- **验收标准**：
  - Given 我输入关键字，When 我搜索，Then 系统返回名称/描述匹配的商品。
  - Given 无匹配结果，When 我搜索，Then 系统显示友好的空结果提示。

## US-07 查看商品详情
- **画像**：P1, P2
- **优先级**：Must
- **关联需求**：FR-PR2, FR-PR4, FR-F1
- **故事**：作为一名员工，我希望查看商品详情，以便了解商品信息并决定是否兑换。
- **验收标准**：
  - Given 我点击某商品，When 进入详情页，Then 我看到图片、描述、积分价格、库存、商品类型（实物/虚拟）。
  - Given 商品为实物，When 我查看详情，Then 提示兑换需填写配送信息。

# 旅程 3 · 兑换商品（员工）

## US-08 确认兑换商品
- **画像**：P1, P2
- **优先级**：Must
- **关联需求**：FR-O1, FR-O2, FR-O3, FR-O4, BR-4, BR-5, BR-6
- **故事**：作为一名员工，我希望确认兑换某商品，以便用积分换取它。
- **验收标准**：
  - Given 我的积分充足且库存充足，When 我确认兑换，Then 系统扣减积分、预占库存并创建成功的兑换订单（无需审批）。
  - Given 我的积分不足，When 我确认兑换，Then 系统拒绝并提示积分不足。
  - Given 库存不足/已售罄，When 我确认兑换，Then 系统拒绝并提示库存不足。

## US-09 填写配送信息（实物商品）
- **画像**：P1, P2
- **优先级**：Must
- **关联需求**：FR-O5, AS-1
- **故事**：作为一名兑换实物商品的员工，我希望填写配送信息，以便商品能寄送给我。
- **验收标准**：
  - Given 我兑换的是实物商品，When 进入兑换流程，Then 系统要求填写收件人、地址、联系方式。
  - Given 配送信息不完整，When 我提交，Then 系统校验并提示必填项。

## US-10 虚拟商品即时履约
- **画像**：P1, P2
- **优先级**：Must
- **关联需求**：FR-O1, AS-2
- **故事**：作为一名兑换虚拟商品/卡券的员工，我希望兑换后即时获得，以便立即使用。
- **验收标准**：
  - Given 我兑换的是虚拟商品，When 兑换成功，Then 无需填写配送信息且系统即时发放（无"待发货"环节），订单状态直接为已完成。

## US-11 兑换成功反馈
- **画像**：P2
- **优先级**：Should
- **关联需求**：FR-F1, FR-O8
- **故事**：作为一名员工，我希望在兑换完成后看到明确的成功反馈，以便确认操作结果。
- **验收标准**：
  - Given 兑换成功，When 流程完成，Then 显示兑换成功页，含订单号、扣减积分、剩余积分及后续指引。

# 旅程 4 · 订单与兑换历史（员工）

## US-12 查看兑换历史
- **画像**：P1, P2
- **优先级**：Must
- **关联需求**：FR-O8, FR-F1
- **故事**：作为一名员工，我希望查看我的兑换历史，以便跟踪我兑换过的商品。
- **验收标准**：
  - Given 我有历史订单，When 我打开兑换历史，Then 按时间倒序展示订单（商品、积分、状态、时间）。
  - Given 我无历史订单，When 我打开页面，Then 显示空状态提示。

## US-13 查看订单详情
- **画像**：P1, P2
- **优先级**：Must
- **关联需求**：FR-O8, FR-O6
- **故事**：作为一名员工，我希望查看单个订单的详情，以便了解其配送/发货状态。
- **验收标准**：
  - Given 我点击某订单，When 进入详情，Then 展示商品信息、消耗积分、配送信息（实物）、当前状态与状态时间线。

## US-14 取消兑换订单（发货前）
- **画像**：P1, P2
- **优先级**：Must
- **关联需求**：FR-O7, BR-7
- **故事**：作为一名员工，我希望在发货前取消兑换订单，以便取回我的积分。
- **验收标准**：
  - Given 订单尚未发货，When 我取消订单，Then 积分自动退回、预占库存释放、订单状态变为已取消。
  - Given 订单已发货，When 我尝试取消，Then 系统拒绝并提示已发货不可取消。
  - Given 订单为已即时履约的虚拟商品，When 我尝试取消，Then 系统按规则拒绝取消。

- **优先级**：Should

# 旅程 7 · 商品与分类管理（管理员）

## US-19 管理商品（增删改/上下架）
- **画像**：P3
- **优先级**：Must
- **关联需求**：FR-PR1, FR-PR2, FR-PR5, FR-F2, FR-F3

  - Given 我填写商品信息（名称、描述、积分价格、库存、分类、商品类型），When 我保存，Then 商品被创建并可在前台展示。

  - Given 我上传图片，When 上传成功，Then 图片存储于本地卷并在商品展示中生效。

## US-21 管理二级分类

- **验收标准**：
  - Given 我新增/编辑分类，When 我保存，Then 分类树更新（支持父/子两级）。
  - Given 某分类下存在商品，When 我删除该分类，Then 系统给出确认并按规则处理（阻止删除或要求迁移）。

# 旅程 8 · 积分管理（管理员/HR）

## US-22 配置积分规则
- **画像**：P3
- **优先级**：Must
- **关联需求**：FR-P3, FR-P4, FR-P5, FR-P7, BR-1, BR-2
- **故事**：作为一名 HR 管理员，我希望配置积分发放规则，以便自动化入职奖励与周期性发放。
- **验收标准**：
  - Given 我配置入职奖励额度，When 新员工注册，Then 系统按该额度自动发放。
  - Given 我配置周期性发放（额度/周期），When 周期触发，Then 系统按规则自动发放给目标员工。
  - Given 我配置积分有效期，When 积分发放，Then 该批积分按配置设定到期时间。

## US-23 手动调整用户积分
- **画像**：P3
- **优先级**：Must
- **关联需求**：FR-P6, FR-F3
- **故事**：作为一名 HR 管理员，我希望手动为指定用户发放或扣除积分，以便处理特殊奖励或纠错。
- **验收标准**：
  - Given 我选择用户并输入调整额度与原因，When 我提交发放，Then 用户余额增加且记录一条带原因的变动。
  - Given 我对某用户扣除积分且余额充足，When 我提交，Then 余额减少并记录变动。
  - Given 扣除额度超过用户余额，When 我提交，Then 系统按规则拒绝或提示。

## US-24 查看用户积分变动记录
- **画像**：P3
- **优先级**：Should
- **关联需求**：FR-P2, FR-F4
- **故事**：作为一名 HR 管理员，我希望查看任意用户的积分变动记录，以便审计与答疑。
- **验收标准**：
  - Given 我选择某用户，When 我查看其积分变动，Then 展示该用户的完整变动明细（类型、金额、时间、操作人/原因）。

# 旅程 10 · 跨服务一致性（系统级，支撑性故事）

## US-28 兑换流程的跨服务一致性
- **画像**：P1, P2（间接，保障兑换可靠）
- **优先级**：Must
- **关联需求**：FR-O10, NFR-4, NFR-5, BR-8
- **故事**：作为一名员工，我希望兑换在涉及多个服务时仍然可靠，以便我的积分与库存始终保持正确。
- **验收标准**：
  - Given 兑换需同时扣减积分与预占库存，When 其中某一步失败，Then 系统执行 Saga 补偿（退回已扣积分/释放预占库存），订单不会处于不一致状态。
  - Given 高并发兑换同一稀缺商品，When 多个请求同时下单，Then 悲观锁保证不超兑。

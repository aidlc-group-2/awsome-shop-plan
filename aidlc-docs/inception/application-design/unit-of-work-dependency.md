## 1. 依赖矩阵（行依赖列）

| 单元 \ 依赖于 | common | Unit7 | Unit2 | Unit3 | Unit4 | Unit5 | Unit6 |

---

## 2. 依赖性质说明
- **common**：被所有后端单元（Unit2~6）**编译期**依赖；自身无依赖，最先构建。
- **Unit7 基础设施**：被所有运行期服务依赖（提供 MySQL/网络/编排）；自身无业务依赖。
- **Unit2 认证 → Unit4 积分**：注册后同步发放入职奖励（运行期，单向）。
- **Unit5 兑换 → Unit3 商品 / Unit4 积分**：库存预占与积分扣减/退回（运行期，单向）。
- **Unit6 网关 → Unit2/3/4/5**：路由与令牌校验。
- **Unit1 前端 → Unit6 网关**：所有业务请求经网关。

**无环**：依赖图为有向无环（DAG），无循环依赖。

---

## 3. 并行性与关键路径
- **可并行**：Unit3 商品 与 Unit4 积分相互无依赖，可并行开发。
- **关键路径**：common → Unit2 认证 / Unit4 积分 → Unit5 兑换（兑换依赖商品与积分）。
- **前端最后**：Unit1 依赖网关与各服务 API 稳定。

---

## 4. 推荐构建顺序
```
common
  → Unit7（基础设施：MySQL/网络）
  → Unit2（认证）
  → Unit6（网关）
  → (Unit3 商品 ∥ Unit4 积分)
  → Unit5（兑换）
  → Unit1（前端）
```

> 集成检查点：Unit2+Unit6 就绪后验证登录鉴权链路；Unit3+Unit4+Unit5 就绪后验证兑换 Saga 与补偿；全部就绪后端到端验证。
